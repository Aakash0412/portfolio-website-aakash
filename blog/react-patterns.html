Modern React Patterns for Enterprise Apps

📅 Dec 2025 ⏱ 6 min read

React gives you freedom — almost too much freedom. A small project can get away with prop drilling and local state, but enterprise-scale codebases need patterns that enforce consistency and reduce cognitive load for every developer on the team.

This post covers three patterns I reach for repeatedly when building large React applications: compound components, render props, and custom hooks.

Pattern 1: Compound Components

Compound components are a way to express relationships between components through a shared parent context. Think of how <select> and <option> work in HTML — neither makes sense alone, but together they form a cohesive API.

// Usage — clean, declarative API
<Accordion>
  <Accordion.Item>
    <Accordion.Trigger>What is your refund policy?</Accordion.Trigger>
    <Accordion.Content>Full refund within 30 days.</Accordion.Content>
  </Accordion.Item>
  <Accordion.Item>
    <Accordion.Trigger>Do you offer support?</Accordion.Trigger>
    <Accordion.Content>24/7 email and chat support.</Accordion.Content>
  </Accordion.Item>
</Accordion>

Why It Works

The parent (Accordion) manages state internally. Children access it via Context. The API is self-documenting — you can see exactly what the component does by reading the JSX.

When to Use

  • Tabs, accordions, dropdowns, modals — any multi-part UI component
  • When you want to give consumers composition control over layout while managing the logic internally

Pattern 2: Render Props

Render props let you share behavior between components by passing a function as a child (or prop). The function receives state/data as arguments and returns JSX.

// A reusable mouse tracker
function MouseTracker({ render }) {
  const [position, setPosition] = useState({ x: 0, y: 0 });

  useEffect(() => {
    const handleMove = (e) => setPosition({ x: e.clientX, y: e.clientY });
    window.addEventListener('mousemove', handleMove);
    return () => window.removeEventListener('mousemove', handleMove);
  }, []);

  return render(position);
}

// Usage
<MouseTracker render={({ x, y }) => (
  <div>Cursor: {x}, {y}</div>
)} />

When to Use

  • When you need to share stateful logic without opinionated UI
  • When custom hooks aren't appropriate (e.g., you need lifecycle-aware rendering)

Render props are less common now that hooks exist, but they're still valuable for components that need to control their own rendering lifecycle.

Pattern 3: Custom Hooks

Custom hooks are the most powerful abstraction in modern React. They let you extract reusable stateful logic into standalone functions that can be composed across components.

// A hook for debounced search
function useDebouncedSearch(query, delay = 300) {
  const [results, setResults] = useState([]);
  const [loading, setLoading] = useState(false);

  useEffect(() => {
    if (!query) { setResults([]); return; }

    setLoading(true);
    const timer = setTimeout(async () => {
      const data = await searchAPI(query);
      setResults(data);
      setLoading(false);
    }, delay);

    return () => clearTimeout(timer);
  }, [query, delay]);

  return { results, loading };
}

// Usage in any component
function SearchBar() {
  const [query, setQuery] = useState('');
  const { results, loading } = useDebouncedSearch(query);

  return (
    <div>
      <input value={query} onChange={(e) => setQuery(e.target.value)} />
      {loading ? <Spinner /> : <ResultsList items={results} />}
    </div>
  );
}

Best Practices for Custom Hooks

  • Single responsibility — Each hook does one thing well
  • Return objects, not arrays — When returning more than 2 values, objects are easier to destructure selectively
  • Handle cleanup — Always return cleanup functions from effects to prevent memory leaks
  • Test independently — Hooks can be tested with @testing-library/react-hooks without rendering full components

Putting It All Together

These patterns aren't mutually exclusive. In a real enterprise app, you might have:

  • A compound component for your design system's DataTable
  • A render prop for a chart component that lets consumers customize tooltips
  • Custom hooks for data fetching, form validation, and authentication state

The key insight is that patterns exist to reduce complexity, not add it. Use them when they genuinely simplify your codebase, and skip them when a simple component with props does the job.

Final Thoughts

Enterprise React is all about managing complexity at scale. These three patterns — compound components, render props, and custom hooks — give you a toolkit for building UIs that are composable, testable, and maintainable. Start with the simplest abstraction that works, and evolve as your needs grow.
